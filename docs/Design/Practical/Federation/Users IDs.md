Users are for humans identifyable by of course, instance name and username, in most places very ActivityPub-esque stylized as `@<username>@<hostname>`. This works for users, but is not sufficient for the underlying protocol to verify and trust a user is indeed on this instance, especially not given that they move and their home instance is deleted.

This is solved by cryptography. The user is not identified by instance nor by username, to machines, the user is identified by a `did:lumina:blablablablabla`, where `blablablablabla` is the user's ed25519 public key, base64 urlencoded. Doing this means a user can not only be identified by a very unique string, but also means important messages can be signed by this user's private key and propogated by other instances with a verifiable way to prove this was once signed by the exact user with this public key.
